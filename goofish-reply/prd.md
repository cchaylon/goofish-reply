## 一、产品概述

### 1.1 产品定位

一款基于 Python 的轻量级闲鱼自动回复客户端工具，帮助用户自动化处理闲鱼聊天消息，通过配置关键词规则实现智能自动回复，提升客服效率。

### 1.2 目标用户

- 闲鱼个人卖家
- 小型闲鱼商家
- 需要自动化回复处理咨询的用户

### 1.3 核心价值

- 降低客服响应时间
- 减少重复性回复工作
- 简单易用的配置方式

### 1.4 产品范围

本工具专注于**自动回复配置**，不包含人工对话、订单管理、商品发布等其他功能。

## 二、用户场景与流程

### 2.1 典型用户场景

**场景一：新手首次使用**

```
用户小王是闲鱼卖家，平时工作繁忙，无法及时回复买家咨询。
1. 下载并安装工具
2. 从闲鱼获取 Cookie 并粘贴配置
3. 设置关键词回复规则（如"价格"→"这个商品100元包邮"）
4. 启动自动回复服务
5. 工具后台运行，自动回复买家咨询
```

**场景二：多商品差异化回复**

```
用户小李在闲鱼卖多种商品，需要针对不同商品设置不同回复。
1. 配置通用关键词回复（全局适用）
2. 为特定商品配置专属回复规则
3. 设置默认回复（兜底）
4. 启动服务，工具自动匹配最佳回复
```

**场景三：配置迁移**

```
用户小张换电脑，需要迁移配置。
1. 导出当前关键词配置
2. 新电脑安装工具
3. 导入配置
4. 重新配置 Cookie
5. 继续使用
```

## 三、功能需求详述

### 3.1 账号登录模块

#### 3.1.1 Cookie 登录

**功能描述**

支持用户输入闲鱼账号 Cookie 进行登录认证。

**详细需求**

| 需求项 | 描述 | 优先级 |
|--------|------|--------|
| Cookie 输入 | 提供文本输入框，支持粘贴完整 Cookie 字符串 | P0 |
| Cookie 保存 | 将 Cookie 加密存储到本地配置文件 | P0 |
| 多账号支持 | 同一工具支持配置多个账号 Cookie | P1 |

**交互说明**

- 用户打开工具设置页面
- 找到 Cookie 配置区域
- 将从闲鱼获取的 Cookie 粘贴到输入框
- 点击"保存"按钮
- 系统提示保存成功

**边界情况**

- Cookie 为空时，提示用户输入
- Cookie 格式错误时，提示格式不正确
- 保存失败时，显示错误信息并允许重试

#### 3.1.2 Cookie 验证

**功能描述**

自动验证用户输入的 Cookie 是否有效。

**详细需求**

| 需求项 | 描述 | 优先级 |
|--------|------|--------|
| 有效性检测 | 在保存 Cookie 时自动验证 | P0 |
| 验证方式 | 携带 Cookie 访问闲鱼 API 接口验证 | P0 |
| 验证结果 | 显示 Cookie 是否有效 | P0 |

**交互说明**

- 用户保存 Cookie 后
- 系统自动发起验证请求
- 验证通过显示绿色对勾
- 验证失败显示红色叉号及错误原因

**边界情况**

- 网络连接失败时，提示网络异常并允许重试验证
- 验证超时（10秒）后提示验证超时

#### 3.1.3 登录状态检测

**功能描述**

实时显示账号的登录状态。

**详细需求**

| 需求项 | 描述 | 优先级 |
|--------|------|--------|
| 状态显示 | 在工具主界面显示当前登录状态 | P0 |
| 状态类型 | 在线（绿色）、离线（灰色）、登录中（黄色） | P0 |
| 定时检测 | 每 5 分钟自动检测一次登录状态 | P1 |

**交互说明**

- 工具启动后自动检测 Cookie 有效性
- 主界面显示账号头像/昵称（如有）和状态图标
- 状态变化时主动更新显示

#### 3.1.4 登录过期提醒

**功能描述**

当检测到 Cookie 失效时，主动提醒用户更新。

**详细需求**

| 需求项 | 描述 | 优先级 |
|--------|------|--------|
| 过期检测 | 自动检测 Cookie 是否过期 | P0 |
| 提醒方式 | 界面弹窗或系统通知 | P0 |
| 过期提示内容 | "登录已过期，请重新配置 Cookie" | P0 |

**交互说明**

- 检测到 Cookie 失效时
- 工具界面弹出提醒
- 或发送系统通知（如已开启通知）
- 用户点击后跳转至 Cookie 配置页面

**边界情况**

- 工具最小化到托盘时，通过系统通知提醒
- 提醒后用户未响应，10分钟后再次提醒

### 3.2 自动回复配置模块

#### 3.2.1 通用关键词回复

**功能描述**

设置全局适用的关键词回复规则。

**详细需求**

| 需求项 | 描述 | 优先级 |
|--------|------|--------|
| 添加规则 | 添加关键词和对应回复内容 | P0 |
| 编辑规则 | 修改已有规则 | P0 |
| 删除规则 | 删除不需要的规则 | P0 |
| 规则列表 | 显示所有通用关键词规则 | P0 |
| 规则排序 | 支持拖拽调整规则优先级 | P1 |

**数据模型**

```python
class KeywordRule:
    id: str                    # 规则唯一标识
    keyword: str                # 关键词
    match_mode: str             # 匹配模式：exact（精确）/ fuzzy（模糊）
    reply: str                  # 回复内容
    enabled: bool               # 是否启用
    created_at: datetime        # 创建时间
    updated_at: datetime        # 更新时间
```

**交互说明**

- 用户进入"自动回复配置"页面
- 选择"通用关键词"标签
- 点击"添加规则"按钮
- 输入关键词和回复内容
- 选择匹配模式
- 保存规则

**边界情况**

- 关键词为空时，提示必填
- 回复内容为空时，提示必填
- 关键词重复时，提示已存在

#### 3.2.2 商品专属关键词

**功能描述**

为特定商品设置专用的回复规则。

**详细需求**

| 需求项 | 描述 | 优先级 |
|--------|------|--------|
| 商品关联 | 输入商品 ID 或标题关联商品 | P0 |
| 专属规则 | 为关联商品设置专属关键词回复 | P0 |
| 规则管理 | 添加、编辑、删除专属规则 | P0 |

**数据模型**

```python
class ProductKeywordRule:
    id: str                     # 规则唯一标识
    product_id: str             # 商品 ID
    product_title: str          # 商品标题
    keyword: str                 # 关键词
    match_mode: str             # 匹配模式
    reply: str                  # 回复内容
    enabled: bool               # 是否启用
    created_at: datetime         # 创建时间
```

**交互说明**

- 用户进入"自动回复配置"页面
- 选择"商品专属"标签
- 点击"添加商品规则"按钮
- 输入商品信息
- 设置该商品的关键词回复规则
- 保存规则

#### 3.2.3 默认回复

**功能描述**

当消息不匹配任何关键词规则时，发送默认回复。

**详细需求**

| 需求项 | 描述 | 优先级 |
|--------|------|--------|
| 默认回复开关 | 开启/关闭默认回复 | P0 |
| 回复内容 | 设置默认回复文本 | P0 |
| 回复模板 | 支持变量替换 | P1 |

**交互说明**

- 用户进入"自动回复配置"页面
- 找到"默认回复"配置区域
- 开启默认回复开关
- 输入默认回复内容
- 保存设置

**边界情况**

- 默认回复关闭时，不发送任何回复
- 默认回复内容为空时，提示必填

#### 3.2.4 回复优先级

**功能描述**

定义多种回复规则的匹配优先级。

**优先级规则**

```
优先级从高到低：
1. 商品专属关键词（针对当前商品配置的专属规则）
2. 通用关键词（全局适用的规则）
3. 默认回复（兜底回复）
```

**详细需求**

| 需求项 | 描述 | 优先级 |
|--------|------|--------|
| 优先级实现 | 系统按优先级顺序匹配规则 | P0 |
| 优先级说明 | 在界面上清晰展示优先级顺序 | P0 |

**交互说明**

- 收到买家消息时
- 系统首先检查是否为商品专属消息
- 如果是，检查是否有匹配的专属关键词
- 如果匹配，发送专属回复
- 如果不匹配，检查通用关键词
- 如果匹配，发送通用回复
- 如果都不匹配，发送默认回复（如已开启）

#### 3.2.5 关键词匹配模式

**功能描述**

支持不同的关键词匹配方式。

**匹配模式**

| 模式 | 描述 | 示例 |
|------|------|------|
| 精确匹配 | 消息内容与关键词完全一致 | 关键词"价格"，仅匹配"价格" |
| 模糊匹配 | 消息内容包含关键词即可 | 关键词"价格"，匹配"价格多少"、"价格便宜"等 |

**详细需求**

| 需求项 | 描述 | 优先级 |
|--------|------|--------|
| 模式选择 | 每条规则可选择匹配模式 | P0 |
| 模式说明 | 界面上说明不同模式的区别 | P0 |

**交互说明**

- 添加或编辑规则时
- 显示匹配模式选择项
- 默认选择"模糊匹配"
- 用户可根据需要切换模式

#### 3.2.6 回复模板变量

**交互说明**

- 用户编辑回复内容时
- 点击"插入变量"按钮
- 从列表中选择变量
- 变量以 {variable} 格式插入到内容中

#### 3.2.7 批量导入关键词

**功能描述**

支持批量导入关键词配置，提高配置效率。

**详细需求**

| 需求项 | 描述 | 优先级 |

#### 3.3.3 自动回复

**功能描述**

根据配置的规则自动发送回复消息。

**详细需求**

| 需求项 | 描述 | 优先级 |
|--------|------|--------|
| 规则匹配 | 按优先级匹配关键词规则 | P0 |
| 消息发送 | 发送回复消息到闲鱼 | P0 |
| 发送延迟 | 可配置回复延迟时间（0-10秒） | P1 |
| 防打扰检测 | 检测买家是否在快速发送消息 | P1 |

**匹配流程**

```
收到消息
    ↓
检查是否为商品专属消息？
    ↓ 是                              ↓ 否
检查商品专属规则              检查通用关键词规则
    ↓                              ↓
找到匹配？              找到匹配？
    ↓是          ↓否           ↓是        ↓否
发送专属回复  继续检查通用规则    发送通用回复  检查默认回复开关
                                  ↓              ↓
                            发送默认回复    不回复
```

**交互说明**

- 收到买家消息
- 系统自动进行规则匹配
- 找到匹配规则后发送回复
- 回复记录自动保存

**边界情况**

- 无匹配规则且未开启默认回复时，不发送回复
- 发送失败时，记录错误并可重试
- 短时间内同一买家多条消息，智能控制回复频率

| 需求项 | 描述 | 优先级 |

| 启动检查 | 启动前检查 Cookie 是否有效 | P0 |
| 启动确认 | 确认后启动服务 | P0 |
| 启动成功 | 显示启动成功提示 | P0 |
| 启动失败 | 显示失败原因 | P0 |

**交互说明**

- 用户点击"启动"按钮
- 系统检查 Cookie 有效性
- Cookie 有效则启动服务
- 显示"服务已启动"
- 界面显示运行状态

**边界情况**

- Cookie 无效时，提示更新 Cookie
- 服务已在运行时，点击无效
- 启动失败时，显示错误信息

#### 3.4.2 停止自动回复

**功能描述**

**详细需求**

- 确认后停止服务
- 断开 WebSocket 连接
- 显示"服务已停止"

#### 3.4.3 服务状态

**状态类型**

| 状态图标 | 不同状态显示不同图标和颜色 | P0 |

**交互说明**

- 工具主界面显示服务状态
- 状态变化时主动更新
- 异常状态时提供错误详情
